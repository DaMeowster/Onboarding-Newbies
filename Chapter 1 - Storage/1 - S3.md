# Object Storage (S3-Compatible) – Client Perspective

Object storage systems expose a simple HTTP-based API for storing and retrieving data as objects.

From a client perspective, S3-compatible storage provides a unified way to interact with data regardless of the underlying implementation or vendor.

:warning: **Note:**  
This chapter is written strictly from the **client point of view**.  
We focus on how applications interact with the system not how it is implemented internally.  
We refer to **S3 and S3 compatible APIs**, for example using **Ceph** as interface.

1. **Data Model, API, and Access Control:** Explain the flat namespace model of S3 (buckets, objects, keys, versions) and how it differs from a hierarchical file system. Explain why the namespace is flat rather than directory-based, what operations a client can perform using the S3 API, What are the different Storage Classes and compare how access is authorized at the client level using S3 API mechanisms (Bucket Policies, ACLs) versus user identities.
A:
במודל הnamespace  השטוח של S3 יש לנו כמה אובייקטים. האובייקט האחסון הכי גדול הוא bucket. בתוך הbuckets יש אובייקטים. למרות שיכול להראות בUI שיש היררכיה בתוך הbucket עם תיקיות שונות, אין באמת. כל האובייקטים נמצאים בתוך הbucket ואין באמת תת-תיקיות. לכל אובייקט יש key ייחודי שהמשתמש נותן לו שמזהה אותו. אם יש לי קובץ שיש לי כמה גרסאות שונות שלו שמורות, ניתן להשתמש בversions. זה יאפשר לנו שכל הקבצים האלו יהיו עם אותו מזהה מה שבדרך כלל אסור, ויהיה להם את המספר גרסה השונה שלפיו ניתן להבדיל. היתרון שאין היררכיה והכל שטוח בתוך הbucket נותן לנו גישות מאוד מהירות לאובייקט, במקום לעבור על היררכיה שלמה מוצאים אותו ישר לפי הid. בעזרת הS3 API ניתן לעשות את הפעולות PUT, GET, DELETE, LIST. בתוך S3 יש storage classes שונים. בגלל שמלכתחילה אנחנו יודעים שיש אזורים שנצטרך לגשת אליהם יותר מאחרים, ואנחנו רוצים לחסוך כסף, אז מתאימים ברמת הbucket או האובייקט storage class שמתאים לכמה אתה מצפה שתיגש אליו. אם אני אגש אליו הרבה וחשוב לי מהירות אז האחסון יעלה לי יותר, אם אני יודע שבקושי אגש וכשאני כן אין לי בעיה לחכות, אני יכול לחסוך כסף ולשלם על אחסון שמותאם לכך.
